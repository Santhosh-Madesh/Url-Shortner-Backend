# URL Shortener Backend

## Overview

This repository is an Express + MongoDB backend for a URL shortening service. It provides a simple REST API to create, resolve, update, delete, and inspect short URLs.

The backend is intentionally self-contained and exposes a clear contract for frontend developers. You should not need to contact the backend developer for normal integration details.

## Technology Stack

- Node.js (CommonJS)
- Express 5
- MongoDB via Mongoose
- dotenv for environment configuration
- cors for cross-origin request handling
- node:dns for custom DNS server resolution

## Setup

1. Install dependencies:

```bash
npm install
```

2. Create a `.env` file at the project root with the following values:

```env
PORT=3000
MONGO_DB_URI=<your-mongodb-connection-string>
```

3. Start the server in development mode:

```bash
npm run dev
```

4. The app will use the configured `PORT` from `.env`.

## Important Backend Configuration Notes

- The backend enables CORS for the origin:

  `https://playful-website-builder--santoshmadesh05.replit.app`

- Allowed HTTP methods are `GET`, `POST`, `PUT`, and `DELETE`.
- Credentials are enabled in CORS.

> If your frontend runs from a different origin, the CORS origin must be updated in `server.js`.

## API Endpoints

### 1. Create a short URL

- Method: `POST`
- Path: `/shorten`
- Body: JSON

```json
{
  "url": "https://example.com/some/long/path"
}
```

Successful response:

- Status: `201`
- Body:

```json
{
  "success": true,
  "message": "Short Url generated for the given url successfully!",
  "data": {
    "_id": "...",
    "url": "https://example.com/some/long/path",
    "shortUrl": "abc12",
    "accessCount": 0,
    "createdAt": "...",
    "updatedAt": "..."
  }
}
```

### 2. Retrieve the original URL

- Method: `GET`
- Path: `/shorten/:shorturl`

Example:

`GET /shorten/abc12`

Successful response:

- Status: `200`
- Body:

```json
{
  "success": true,
  "message": "The full url retrived for the corresponding short url",
  "data": {
    "_id": "...",
    "url": "https://example.com/some/long/path",
    "shortUrl": "abc12",
    "accessCount": 1,
    "createdAt": "...",
    "updatedAt": "..."
  }
}
```

> Note: Each successful retrieval increments `accessCount` by one.

### 3. Update the target URL

- Method: `PUT`
- Path: `/shorten/:shorturl`
- Body: JSON

```json
{
  "url": "https://example.com/updated/path"
}
```

Successful response:

- Status: `200`
- Body:

```json
{
  "success": true,
  "message": "Url updated successfully",
  "data": {
    "_id": "...",
    "url": "https://example.com/updated/path",
    "shortUrl": "abc12",
    "accessCount": 1,
    "createdAt": "...",
    "updatedAt": "..."
  }
}
```

### 4. Delete a short URL record

- Method: `DELETE`
- Path: `/shorten/:shorturl`

Successful response:

- Status: `204 No Content`

> The backend sends a 204 response for successful deletion. Many clients will not return a body with this status.

### 5. Get short URL stats

- Method: `GET`
- Path: `/shorten/:shorturl/stats`

Successful response:

- Status: `200`
- Body:

```json
{
  "success": true,
  "message": "Url stats retrived successfully",
  "data": {
    "_id": "...",
    "url": "https://example.com/some/long/path",
    "shortUrl": "abc12",
    "accessCount": 5,
    "createdAt": "...",
    "updatedAt": "..."
  }
}
```

## Request and Response Behavior

- For invalid input, the backend returns a `400` error with a JSON payload.
- For missing short URLs, the backend returns `404`.
- For internal failures, the backend returns `500`.
- All error responses follow this shape:

```json
{
  "success": false,
  "message": "<error message>"
}
```

## Data Model

The URL document includes:

- `url` — original long URL string
- `shortUrl` — unique short code string
- `accessCount` — number of times the short URL was retrieved
- `createdAt` / `updatedAt` — timestamps generated by Mongoose

## Backend Behavior Notes for Frontend Integration

- The backend expects JSON request bodies for `POST /shorten` and `PUT /shorten/:shorturl`.
- The `shortUrl` field is generated by the backend and is always returned as an alphanumeric string.
- The backend resolves short URLs using `shortUrl` as the unique key.
- `DELETE /shorten/:shorturl` is idempotent: deleting a non-existent code returns `404`.

## Example JavaScript Fetch Usage

```js
// Create
const createResponse = await fetch('/shorten', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ url: 'https://example.com' })
});
const createData = await createResponse.json();

// Retrieve
const getResponse = await fetch('/shorten/' + createData.data.shortUrl);
const getData = await getResponse.json();
```

## Troubleshooting

- If the server fails to start, verify `PORT` and `MONGO_DB_URI` in `.env`.
- If CORS blocks requests, confirm your frontend origin is permitted in `server.js`.
- If MongoDB does not connect, ensure the database URI is valid and accessible.

## Files of Interest

- `server.js` — main Express app, middleware, CORS config, route mounting
- `routes/urlRoutes.js` — public API route definitions
- `controllers/urlControllers.js` — request validation, business logic, error handling
- `models/urlModels.js` — Mongoose schema and database operations
- `db/connectDB.js` — MongoDB connection
- `middlewares/errorMiddleware.js` — centralized JSON error responses
- `utils/shortCodeGenerator.js` — generates random short URL strings

## Additional Notes

- This backend is intended as a JSON API only and does not render HTML.
- Any frontend integration should use the API contract described above.
